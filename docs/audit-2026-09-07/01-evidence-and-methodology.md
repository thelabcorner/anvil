# 01 — Evidence and Methodology Audit

## 1. Evidence hierarchy

ANVIL needs an explicit evidence hierarchy because the project historically mixed purpose-built synthetic files, repo-generated corpora, local source files, real binaries, and canonical public corpora in the same narrative.

### Tier A — external canonical corpus evidence

Highest weight:

- canonical Silesia, each file compressed independently;
- canonical enwik8;
- future Pizza&Chili Real/Logs;
- future third-party binary/media corpora.

Use Tier A for claims about general-purpose compression and external standing.

### Tier B — real application / system files

- PE/ELF executables;
- SQLite/database files;
- DICOM/medical images;
- PDFs, archives, media containers;
- real logs or telemetry not generated by ANVIL.

Use Tier B for domain-specific mechanisms and transfer testing.

### Tier C — purpose-built falsification corpora

Examples: `synth-arith.bin`, `synth-jitter.bin`, `synth-timeseries.bin`.

These are excellent for answering questions such as “does the detector work if the signal exists?” or “is the representation mathematically capable of expressing this family?” They are **not** evidence that the signal is common in nature.

### Tier D — repo-generated stress/self-test corpora

Examples: generated JSONL/log/structured JSON files designed around repetitive records.

These are useful for mechanism development, regression control, and ablation. They are the lowest-evidence tier for generalization because the generator can accidentally encode the exact regularity the mechanism was designed to exploit.

### Binding interpretation rule

A lower-tier win can justify **an experiment on a higher tier**. It cannot be promoted into a higher-tier claim by narrative.

## 2. Standard-corpus benchmark integrity

`tools/bench_ratio.py` is now the best benchmark harness in the project for ratio-first external evidence.

Properties:

- one `(file × codec)` independent cell;
- checkpoint append after each cell;
- flush + `fsync` after each cell;
- skip completed successful cells on restart;
- canonical manifest size+MD5 checks;
- exact compressed bytes per file;
- decompression + SHA-256 equality;
- per-cell wall time and process memory.

All 52 current Silesia/enwik8 baseline cells carry `VALID_100MS_NONRECURSIVE` timing status.

## 3. Timing instrumentation correction

The first harness sampled process trees every 5 ms and recursively enumerated children. That measurement code consumed enough CPU to distort the codec being measured.

The replacement:

- samples every 100 ms;
- samples the direct codec process only;
- uses Windows `peak_wset` where available;
- preserves old timing under `legacy_*` columns;
- marks old values `INVALID_5MS_RECURSIVE_POLL` rather than deleting them;
- refuses timing refresh if authoritative compressed bytes or roundtrip status change.

The correction materially changed wall time without changing bytes. Representative ANVIL cells:

| file | old | repaired | bytes unchanged |
|---|---:|---:|---:|
| dickens | ~73.5 s | ~52.4 s | 2,827,810 |
| mozilla | ~311.3 s | ~232.2 s | 13,806,172 |
| nci | ~195.3 s | ~164.3 s | 1,497,441 |
| webster | ~331.8 s | ~279.0 s | 8,340,089 |

Lesson: **measurement code is part of the experiment**. Benchmark overhead must itself be profiled or bounded.

## 4. Current compiler confound

The refreshed standard reference timings and the first BWT timings are not directly comparable.

- standard reference refresh: pre-BWT `clang-cl` build;
- BWT bring-up: C language enabled for `libsais.c`; direct shell lacked Windows SDK `rc.exe` / clang registration;
- recovery build: Visual Studio 2022 developer environment with MSVC `cl` for C and C++.

Compressed byte counts remain comparable because the wire is deterministic and exact roundtrip was checked. Throughput is **directional only across these build groups**.

### Required repair

Before any BWT speed/frontier statement:

1. standardize one compiler/toolchain for ANVIL, Brotli helper, and libsais;
2. record compiler ID/version, compile flags, CPU affinity/power state, and executable hash in benchmark metadata;
3. rerun Brotli/BWT reference cells under the same build;
4. use median ≥3 for speed claims.

## 5. Claim hygiene lessons

### 5.1 `EXTENDS_FRONT` is not a frontier claim

Iteration 8 found five historical `EXTENDS_FRONT` rows that had been missed by the narrative. A deeper audit showed all five sat inside a gap between two reference configurations and were decode-dominated.

The resulting vocabulary is correct and should stay:

- `FRONT-GAP`: non-dominated because the reference grid leaves a rectangle uncovered;
- `FRONT-CROSSING`: non-dominated and not a grid-gap artifact;
- `DEGENERATE`: ratio ≥ 0.95, not meaningful compression-front evidence.

Only `FRONT-CROSSING` should support language such as “crossed the frontier.”

### 5.2 A number in a document is a claim, not a fact

The project propagated at least two stale/unreachable tallies and one un-attributed major byte improvement. Therefore cumulative counts and historical “best” claims must be recomputed from source artifacts at write time.

### 5.3 Transform-aware reference controls are mandatory

ARI-REF looked close to raw Brotli on `synth-arith.bin` until Brotli was also given a simple delta+zigzag representation. The transformed Brotli result was dramatically smaller.

Binding rule:

> If ANVIL benefits from a reversible representation, reference codecs must also be tested on the same representation whenever that comparison is semantically possible.

Otherwise the experiment measures “ANVIL knew a filter” rather than compressor quality.

## 6. Current provenance debt

### 6.1 Un-attributed generated.json ratio move

Between historical commits, `anvil-mdl-rans` on generated.json moved from 104,437 to 89,589 bytes and `anvil-shape-rans` from 101,858 to 92,300. The ledger did not attribute this change to an experiment.

This is still worth resolving because it may reveal a transferable default/config interaction. It is **not urgent for external standing** because generated.json is Tier D, but it is urgent for research reproducibility.

### 6.2 Ratio-first/BWT work is not yet in the main ledger

The new Silesia/enwik8 and BWT evidence lives in CSV/source/session history but has not been consolidated into `RESEARCH_LEDGER.md`. This audit should be treated as the temporary authoritative synthesis until a ledger appendix is added.

## 7. Experimental accounting improvements to adopt

Every future benchmark row should carry or be joinable to:

- source file hash;
- codec build hash;
- compiler/version + flags;
- format revision;
- transform ID;
- backend ID;
- backend internal mode/postcoder if applicable;
- compressed bytes;
- roundtrip verdict;
- encode/decode timing protocol;
- peak memory protocol;
- executable/decompressor size;
- corpus evidence tier.

This makes “what changed?” mechanically answerable instead of archaeological.

## 8. A better experimental unit: regret, not only winner

As ANVIL becomes a backend portfolio, report **routing regret**:

```
regret = chosen_payload_bytes - oracle_min_payload_bytes
```

Compute it per block, per file, and aggregate.

This separates two problems:

1. backend quality: how good are the candidate codecs?
2. routing quality: how close does the cheap router get to an expensive encode-all oracle?

Without regret accounting, a router can look good merely because one backend dominates most inputs.
